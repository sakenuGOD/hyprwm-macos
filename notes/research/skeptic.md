## 0. Что видит пользователь и что даст починка

| Что видно | Причина (коротко) | Уверенность |
|---|---|---|
| Cmd+T в Ghostty: окно «пропало» (на месте плитки пусто) | новое окно вкладки спрятано альфой 0 до popin, потом опознано как «вкладка», и **альфу никто не возвращает** | [V] код + лог |
| Telegram/Finder обрезаны прямоугольником, без скругления и тени, навсегда | минимум окна **не выучивается**, если окно уже стоит на минимуме; раскладка даёт плитку меньше минимума → клип держится вечно | [V] код + лог (десятки «держу в плитке») |
| Окна наложились после быстрого открытия многих терминалов | (1) параллельные configure-потоки без порядка: поздний старый AX-вызов перезаписывает рамку; (2) после окончания анимации ни движок, ни демон не следят за рамкой окна; (3) таймауты 0.6 с возвращают окну видимость на «родном» месте | [V] механизм в коде, [H] что именно он сработал в том эпизоде |
| Через какое-то время новые окна перестают тайлиться вообще | кэш AX на 256 элементов без вытеснения: после 256 разных wid `lookup` всегда NULL | [V] код (бомба замедленного действия) |
| То же для движка: окна перестают анимироваться/прятаться | 64 слота, освобождаются только по EV_GONE; скрытые вкладки держат слоты; `errors` никто не читает | [V] код |
| Серый прямоугольник/полоса при возврате Telegram | подложка цвета `windowBackgroundColor` (серый) в полосе B−A, пока Telegram перерисовывается; либо Qt выбросил содержимое, пока окно было с α=0 за экраном | [H] — две гипотезы, есть различающий тест (§2, S7) |
| «Подвисание» при быстрых повторных биндах | глобальный `holding`: каждая новая пачка замораживает **все** уже едущие окна до 17 мс; плюс главный цикл демона блокируется AX-вызовами | [V] код |

## 1. СКЕПТИК: претензии к коду

### S1. Cmd+T (вкладка Ghostty/Finder/Safari) — окно остаётся с α=0 навсегда [V]
- Механизм:
  1. `hide_newbies` (hyprwm.py:763–769): новое окно вкладки — обычное, тайловое → `c.alpha(wid, 0.0, 0, 0.0, frm=0.0)`, из `newbies`/`optimistic` удаляется.
  2. `sync` (hyprwm.py:369–383): окно опознано как близнец ушедшей вкладки; лист переименован,
     `self.target[w["wid"]] = self.target.pop(twin)` (378); в `opened` НЕ попадает.
  3. `apply` (hyprwm.py:239): `if not force and self.target.get(wid) == to: continue` — цель та же → окно пропущено.
     Даже если бы не пропустилось, ветка `else` (249–265) возвращает альфу только для `restoring`.
  Итог: никакой путь не шлёт `alpha 1` новому окну вкладки.
- Доказательство в живом логе /tmp/hyprwm.log:
  `2061: 22:22:28.461 новое окно Ghostty 3145 спрятано до popin (через 19 мс после создания)` →
  `2062: вкладка Ghostty: 180 -> 3145 (место в раскладке то же)`; то же `2168–2169` для 3876.
- Как правильно: в `sync` при переименовании листа — `c.alpha(new, 1.0, 0, 0.0)` (вкладка у macOS
  появляется мгновенно, анимация не нужна), а также передать подложку (`deco`) и слот движка
  (`OP_FORGET` для `twin`, если он больше не на экране). Альтернатива: в `hide_newbies` не прятать окно,
  если на его рамке (±TOL) уже стоит тайловое окно того же pid — это вкладка.

### S2. Минимум окна не выучивается, если окно уже на минимуме → вечный прямоугольный клип [V]
- Механизм: `configured` (hyprwm.py:338–343) учит минимум, только если окно **сдвинулось** в сторону цели:
  `g > t + TOL and abs(g - p) > TOL and (p - g) * (p - t) > 0`. Окно, которое уже стоит на минимуме (p == g),
  не учится никогда, и ветка 349–350 только пишет «держу в плитке». Раскладка (tile.py:106) снова даёт плитку
  меньше минимума, движок держит клип (anim4.c:382 `an = w->stable < 2`, клип 401–404 прямоугольником).
- Доказательство: hook/minsize_app.json = `{"Telegram": [0, 584.0], ...}` — ширина Telegram не выучена (0).
  Лог: `окно Telegram 28 стоит (470, 584) вместо (310.0, 448.0) — держу в плитке` и
  `окно Finder 2087 стоит (459, 444) вместо (200.0, 444.0)` — повторяются десятки раз (21:53–22:13), ни разу
  не сопровождаются «минимум ...».
- Ещё: tile.py:91 `MINS.get(wid, (MIN_W, MIN_H))` — выученное `[0, 584]` даёт минимум ширины **0** (меньше
  дефолта 200); надо `max(learned, default)` по каждой оси.
- Это и есть «Telegram идёт обрезанным без скругления»: клип — прямоугольный CGRegion, режет правые/нижние
  скругления и тень (см. wayland_gap §1.4; evidence/square_corner.png).
- Как правильно: (а) считать минимумом `got` по оси, если ax_frame вернул успех, окно стабильно ≥90 мс и
  `got > to + TOL` — независимо от `pre`; (б) хранить минимум по (owner, роль окна), не только по owner;
  (в) когда сумма минимумов не влезает (tile.py:106 ветка пропорций) — это ситуация Hyprland «окно больше
  плитки»: решать политикой (float/overflow), а не вечным клипом.

### S3. Настоящие гонки configure: N потоков на одно окно, без порядка и без отмены [V]
- Механизм: `configure` (hyprwm.py:294–318) — на каждое событие новый `threading.Thread` на каждое окно.
  Быстрые события (открытие 5 терминалов за 1.3 с — лог 1755–1774; быстрые бинды) → у одного окна 2–4 живых
  потока, каждый делает `ax_frame` = позиция→размер→позиция (axlib.c:82–84) с таймаутом 0.25 с на сообщение.
  Порядок прихода в приложение не гарантирован → **поздний вызов со старой целью ставит окну старую позицию и
  размер**. `configured` (332) отбрасывает устаревший ответ (`self.target.get(wid) != to`), но рамку не
  исправляет.
- Почему это видно как наложение: движок по окончании анимации, если рамка совпала, ставит `settling=0`
  (anim4.c:375) и дальше `frame_win` выходит на `if (!w->settling) return 0;` (369) — **окно больше не
  трансформируется**, и его реальная (устаревшая) рамка видна как есть. Демон пропускает окно, пока цель не
  меняется (hyprwm.py:239), `realign` зовётся только по отпусканию мыши (733–734).
- Как правильно: одна очередь configure на окно (последняя цель побеждает, старые отменяются: «серийный
  номер» цели проверять в потоке перед каждым AX-вызовом), один рабочий поток на приложение (AX-сообщения
  приложению всё равно сериализуются его главным потоком). Плюс S4.

### S4. Нет слежения за рамкой окна в покое (дрейф не замечается) [V]
- anim4.c:366–369: окно без анимации и без `settling` не проверяется. Демон сравнивает реальную рамку с
  целью только в `realign` после отпускания мыши (hyprwm.py:810–824).
- Источники дрейфа: S3; приложение само меняет размер (Ghostty — смена шрифта/сетки, Telegram — восстановление
  геометрии, AppKit `constrainFrameRect` после смены экрана); встроенный тайлинг macOS 26 (axlib.c:191–194 сам
  описывает, что WindowManager «возвращает окно в плитку»).
- Движку это почти бесплатно: `actual()` уже вызывается для каждого занятого слота каждый тик (anim4.c:351).
- Как правильно: в `frame_win` при `!settling` сравнить A с последней целью и при расхождении >1 pt постить
  `EV_MOVED(wid, A)`; демон на `EV_MOVED` — либо ретаргет (как Hyprland: окно в плитке главнее), либо
  перевод в float, если это пользовательский drag.

### S5. «Окна наложились при быстром открытии» — дополнительные пути, кроме S3 [V механизм]
1. Таймауты: `newbies` живут 0.6 с (hyprwm.py:752), `optimistic` через 0.6 с возвращает окну α=1
   (779–783). Если AX приложения не ответил за 0.6 с (под нагрузкой пачки окон; backoff в `wm_info`
   162 — wayland_gap §1.8), окно становится видимым **на месте, которое выбрал macOS (каскад)**, поверх плиток.
2. Вечный кэш «не тайлить»: `wm_info` (155–171) кладёт первый ответ AX в `self.info` навсегда. Если в момент
   создания окно ещё не `AXStandardWindow` или размер ещё не settable — `type: other` навсегда → окно
   плавает поверх. Сбрасывается только командой `reset` (499–500).
3. Главный цикл блокируется: `exec Ghostty --new` → `pgrep` + обход всего меню AX глубиной 7
   (hyprwm.py:648–650, axlib.c:206–233, таймаут 0.5 с на сообщение); `ax_tileable` на главном потоке
   (таймаут 0.25 с, axlib.c:24,37); `apply` спит до 50 мс (279–280); `eng.alive()` спит 50 мс раз в 2 с
   (engine.py:42). Всё это время новые окна не прячутся и не вставляются.
4. Фокус за курсором меняет точку вставки: лог 1772–1777 — между открытиями терминалов
   `фокус за курсором -> Telegram 28`; `follow_mouse` пишет `s["focus"]` (807), и следующий терминал
   делит Telegram, а не последний терминал. Это не наложение, но «встаёт не туда».
5. Гонка записи `wid_max`: демон пишет `h.wid_max = top` (hyprwm.py:696–697), движок — `h->wid_max = m`
   (anim4.c:460), оба без атомарного RMW. Демон может поднять `wid_max` выше ещё не просканированных номеров →
   для них нет `EV_NEW` → окно не спрятано до первого показа. Скан ещё и останавливается после 24 пропусков
   подряд (anim4.c:454) — пачка короткоживущих окон (меню, подсказки, наши же подложки hyprdeco: каждое новое
   тайловое окно рождает ещё одно окно-подложку, deco.py:43) может разорвать цепочку. [H] насколько часто.
- Как правильно: вставка в раскладку по `EV_NEW` + `win_pid_level` (уже есть) без ожидания AX; AX — только
  для отсева диалогов, с повтором каждые 16 мс первую секунду; `info` кэшировать только положительный ответ;
  `wid_max` пишет только движок (демон — отдельное поле «подсказка»).

### S6. Глобальный `holding` замораживает все едущие окна на каждой новой пачке [V]
- anim4.c:321–327: каждая `OP_GEOM` ставит `w->held = 1` и **глобальный** `ch->h.holding = 1`; пока держим
  (465–490), `frame_win` не шагает ни позицию, ни размер, ни **альфу** (343–349). Предел — `hold_max`,
  который демон не задаёт (grep: только поле в chan.py:53) → 0.017 с.
- Эффект на быстрых биндах (resize с автоповтором, перебор focus/move): каждые ~30–50 мс все окна
  останавливаются до кадра → «ступеньки». Hyprland ничего не ждёт.
- Как правильно: держать только окна этой пачки, у которых `needs`; уже едущие — ретаргет без остановки;
  альфу не держать.

### S7. Скрыть/вернуть: парковка за экраном с α=0 вместо системного механизма [V код, H следствия]
- hide: α→0, потом `OP_WARP` в `x = area.right + 200` (hyprwm.py:585–591). Окно остаётся на Space, в списке
  окон, в Mission Control/App Exposé; AppKit может вернуть его на экран сам (`constrainFrameRect`) [H].
- unhide (595–609) не смотрит на Space: скрыли на столе 1, вернули на столе 2 → окно ворпнуто на столе 1 с α=0,
  `restoring` висит до визита на стол 1. Docstring обещает «в раскладку текущего стола».
- Серый при возврате Telegram — две гипотезы:
  (а) подложка: `deco` красит `NSColor.windowBackgroundColor` (hyprdeco.m:101), а `sample` идёт только по
  окнам на экране (`onScreenWindowsOnly:YES`, hyprdeco.m:31) и только раз в 2 с в покое (hyprwm.py:724–729) —
  у только что вернувшегося окна цвет не тот; полоса B−A видна, пока Telegram перерисовывается под новый размер
  (configure шлётся сразу, hyprwm.py:271–275).
  (б) окно с α=0 за экраном — «невидимо» для сервера → Qt получает смену occlusion и выбрасывает содержимое;
  при возврате первые кадры — фон без контента [H]. Символы для проверки подписки есть:
  `_SLSPackagesEnableWindowOcclusionNotifications` 187161058 [V адрес].
  Различающий тест — сценарий T4.
- Как правильно: «special workspace» = отдельный Space: `_SLSMoveWindowsToManagedSpace` 186fee37c /
  `_SLSSpaceAddWindowsAndRemoveFromSpaces` 186fe69f4 [V адреса] (так делает yabai для scratchpad);
  возврат — `F_FROM` + α 0→1 в целевую плитку одним `commit`.

### S8. Утечки и исчерпание ресурсов [V]
1. **AX-кэш (axlib.c:10–44)**: 256 слотов, ключ — wid, вытеснения нет; `ax_forget` объявлен
   (hyprwm.py:58), но **нигде не вызывается** (grep). `lookup_locked` кэширует **все** окна приложения при
   каждом промахе. Когда слоты кончились: `if (slot < 0) continue;` стоит **до** `if (id == wid) found = el;`
   (33–38) → `lookup` всегда NULL → `ax_tileable = -1`, `ax_frame = -1` для любого нового окна. Лог уже
   показывает `configure окна 2121: ошибка -1` (21:53:59.711). Как правильно: вызывать `ax_forget` на
   `EV_GONE`; при полном кэше вытеснять самый старый; найденный элемент возвращать даже без слота.
2. **Слоты движка (chan.h:12, CH_NW 64)**: `slot(..., alloc)` выделяет слот на любую команду кроме FORGET
   (anim4.c:276), в т.ч. `alpha 0` «оптимистично» спрятанным диалогам. Освобождение — только при
   `CGXWindowByID == NULL` или `OP_FORGET`, а `chan.forget` демон **не вызывает** (grep). Скрытые вкладки
   Ghostty живы и держат слоты вечно. При 64 слотах новые команды молча теряются: `ch->h.errors++` (277),
   демон `errors` не читает (grep: только поле в chan.py:48).
3. **Подложки**: `deco.drop` только по `EV_GONE` (hyprwm.py:705). Кольцо событий 128 (chan.h:15), движок
   пишет без проверки читателя (anim4.c:160–165), клиент молча пропускает старое (chanlib.c:113) — при
   блокировке демона (S5.3) `EV_GONE` теряется → окно-подложка в hyprdeco живёт вечно (кандидат на «осиротевшие
   серые прямоугольники» B3 из evidence/video_audit.md). Также `info`, `miss`, `pids`, `owner`, `mins`
   растут без очистки (hyprwm.py:129–137).
4. `deco.place` возвращает wid подложки из словаря, который заполняет **другой поток** по ответу hyprdeco
   (deco.py:24–28, 45–50): у окна, чья подложка создана в этом же цикле (`sync` → `deco.ensure`, hyprwm.py:406),
   первой анимации подложка не достаётся (`u` = None, 259–261).

### S9. Рассинхрон документации и кода (опасно для следующих сессий) [V]
- hyprwm.py:268–270 и HANDOFF сессия 6: «по сжимающейся оси — прежний размер, конечный — по EV_DONE».
  Код шлёт **конечный** размер сразу по обеим осям (273), `EV_DONE`/`EV_SETTLED` демон не обрабатывает
  (цикл событий 698–705 — только NEW и GONE). Следствие: при сжатии из широкой рамки буфер становится
  меньше B на весь ход → полоса подложки (часть «серых полос»). Решить, какое поведение верное, и привести
  одно к другому.

### S10. Опрос вместо событий — что добавить к wayland_gap §1.3 [V]
- Движок в простое будит главный поток WS **125 раз/с навсегда**: `at = now + idle_poll` (anim4.c:499),
  `idle_poll = 0.008` (engine.py:108). Каждый такой тик: до 64+24 `CGXWindowByID` (скан новых wid 452–461) и
  `actual()` по всем слотам. Без отдельного канала пробуждения опрос команд в простое неизбежен, но его период можно поднять до кадра
  (16.7 мс) и сканировать новые wid не чаще; лучше — пробуждать тик по событию сервера [H].
- `hide_newbies`: на каждый новый wid, не попавший в снимок, 3 RPC (`SLSGetWindowOwner`, `SLSConnectionGetPID`,
  `SLSGetWindowLevel`, hyprwm.py:69–71) каждые 16 мс до 0.6 с.
- Цвет подложек: `SCShareableContent` (полный перечень окон) на **каждое** тайловое окно раз в 2 с
  (hyprdeco.m:31, hyprwm.py:724–729). Нативно и дешевле: `_SLSHWCaptureWindowList` 186fa5d40 [V адрес]
  (то же, что использует сам WS для снимков), или цвет края брать в движке.
- `follow_mouse` зовёт `ax_focus(..., raise=1)` (806): каждый переход курсора = активация процесса +
  `AXRaise` — меняет z-порядок и меню; во время анимации окна «проезжают» под курсором → лишние
  активации (лог: 4 переключения фокуса за 0.5 с, 21:57:23.859–24.311).

### S11. Мелочи с риском [V]
- `command()` обрабатывает ровно одну команду за итерацию и делает `continue` (hyprwm.py:719) — при автоповторе
  бинда `follow_mouse`/`hide_newbies`/`sync` голодают.
- `put_clip`/`put_under` берут соединение окна по жёсткому смещению `*(win + 0x30)` (anim4.c:205, 227) —
  в HANDOFF подтверждено вживую для 26.7.1, но в коде нет проверки версии/сборки WS → после обновления macOS
  запись по чужому указателю внутри WS. Нужна проверка build-id WS в install4.py (SHAPE_OFF 0x170 — то же).
- `close_anim` → при отказе закрытия (диалог «Сохранить?») окно уже сжато popin 92 % со stretch
  (544), а `check` возвращает только альфу (557); геометрия восстановится лишь через `sync`→`opening`→popin
  заново (двойная анимация).
- При старте демона скрытые окна возвращаются `everything=True` (672) → вставляются как новые → popin
  (hyprwm.py:241: `restoring` пуст) — Telegram «прыгает» при каждом перезапуске демона (лог 1752–1754).

## 3. СБОРЩИК БАГОВ: стресс-сценарии для живого прогона (прогоняет основной агент)

Общая фиксация для всех: `python3 hook/scripts/rec2.py <сек> "<команда>" /tmp/rec2_<имя>` (кадры ~50 к/с,
видят наш трансформ и клип, `times.txt` — мс от запуска команды) + лог: засечь время старта и потом
`awk '$1>="HH:MM:SS"' /tmp/hyprwm.log` (в лог самим не писать — его пишет демон). После каждого сценария: `echo status | nc -U /tmp/hyprwm.ctl`
(дерево, mins, engine.active) и сверить с картинкой. Для «реальной» рамки — `chan` (`Engine.real()`),
для видимой — CGWindowList.

**T1. Быстрое открытие многих окон (известный баг «наложились»).**
- Действие: 6× `echo "exec Ghostty --new" | nc -U /tmp/hyprwm.ctl` с паузой 50 мс, потом 6× с паузой 0.
- Ожидаемые баги: S3 (поздний AX со старой целью), S4 (никто не замечает), S5.1 (α вернулась через 0.6 с
  на каскадном месте), S5.3 (блокировка главного цикла обходом меню).
- Объективно: через 2 с сравнить для каждого wid `Engine.real()` с `layout()` (команда status + chan);
  любое расхождение >TOL у покоящегося окна = баг S3/S4. В rec2 — кадры, где окно видно вне своей плитки.
  В логе — интервалы между «команда 'exec…'» и «новое окно … -> в раскладку»; строки «спрятано» отсутствуют
  у части окон = S5.1/S5.5.

**T2. Быстрые повторные бинды.**
- Действие: 20× `resize 40 0` по 30 мс; затем чередование `move l`/`move r` 10× по 40 мс.
- Ожидается: S6 (окна стоят до кадра при каждой команде — в rec2 повтор одной позиции 2+ кадра подряд у
  уже едущего окна), S3 (итоговый размер ≠ цели), S11 (follow_mouse/hide_newbies не выполняются).
- Объективно: траектория левого края окна по кадрам rec2 — монотонна ли, есть ли «плато» ≥2 кадра;
  `h.last_dt` и `nactive` из chan.

**T3. Переключение Spaces во время анимации.**
- Действие: запустить `move l` и через 60 мс Ctrl+→ (смена стола), через 300 мс назад.
- Ожидается: движок продолжает ставить трансформ/альфу окнам ушедшего стола; подложки hyprdeco
  (`NSWindowCollectionBehaviorManaged`, hyprdeco.m:90) принадлежат тому столу, где были созданы →
  [H] серый прямоугольник на чужом столе; снимок `stable=0` пропускает циклы (hyprwm.py:689–690).
- Объективно: rec2 обоих столов; в логе «рабочий стол N»; после возврата — `status` (дерево не потеряло окна),
  реальные рамки = цели.

**T4. Скрыть/вернуть (известный баг Telegram «серый экран»).**
- Действие: на столе с Telegram: `hide` (фокус на Telegram) → 1 с → `unhide`. Повторить с разницей:
  (а) как есть; (б) предварительно `sample` подложки (подержать окно в покое >2 с перед hide);
  (в) hide, переключить стол, unhide (S7, unhide на чужом столе).
- Ожидается: серый в полосе B−A (гипотеза S7а) или серый на всём окне (S7б); (в) — окно не появляется.
- Объективно: в кадрах rec2 сравнить цвет серого с цветом подложки (`color …` в stdout hyprdeco не
  логируется — смотреть по пикселю: серый ровно в полосе B−A = подложка; серый по всей рамке A = приложение).
  Отдельно: вклад подложки снимается, если окну временно не ставить under (переменная окружения/флаг —
  не трогая код до теста нельзя; поэтому различать по геометрии серого).

**T5. Telegram/Spotify с минимальным размером (известный баг «обрезан без скругления»).**
- Действие: Telegram + 3 терминала на одном столе (плитка Telegram < его минимума); затем `balance`.
- Ожидается: S2 — «держу в плитке» без «минимум …»; прямоугольный срез справа/снизу, без скругления и тени.
- Объективно: лог; `minsize_app.json` после теста (выучена ли ширина); кадр rec2 правого нижнего угла
  Telegram (скругление есть/нет — сравнить с evidence/square_corner.png).

**T6. Закрытие окна приложением (Cmd+W) и нашим `close`.**
- Действие: (а) в одном из 3 терминалов Cmd+W; (б) `close` у окна с несохранённым документом (TextEdit).
- Ожидается: (а) окно исчезает мгновенно, соседи стартуют через `EV_GONE`→снимок (лог «ушло из раскладки
  (через N мс после движка)»), растущие соседи — полоса подложки (S9); (б) S11: popin-сжатие, потом
  возврат только альфой, потом второй popin.
- Объективно: задержка из лога; кадры rec2 первые 100 мс; для (б) — число анимаций в rec2.

**T7. Cmd+T в Ghostty (известный баг «окно пропало»).**
- Действие: окно Ghostty в плитке, Cmd+T; затем Cmd+Shift+] / [ (переключение вкладок); Cmd+W вкладки.
- Ожидается: S1 — после Cmd+T плитка пустая (видны обои/подложка), в логе пара строк «спрятано до popin» +
  «вкладка …». Переключение назад на старую вкладку — окно видно (у старого wid α не трогали).
- Объективно: rec2 + проверить α через chan (`cur_alpha` у слота нового wid = 0.0).
  Дополнительно [H]: если macOS на мгновение показывает обе вкладки, одна из них вставится как новое
  окно — в логе «новое окно Ghostty … -> в раскладку» вместо «вкладка» и двойная перекладка.

**T8. Несколько окон одного приложения.**
- Действие: 3 окна Finder + 2 Ghostty; перебирать `focus` по всем; закрыть средний Finder; открыть новое
  окно Finder (Cmd+N) при фокусе на Ghostty.
- Ожидается: минимум учится по owner (S2) — одно маленькое окно Finder портит раскладку всех Finder;
  `ax_focus` поднимает окно, но фокус клавиатуры на другом окне того же приложения [H]; вкладочная эвристика
  (`twin`) может спутать новое окно Finder с закрытым, если оно открылось ровно на его месте
  (hyprwm.py:369–370) — раскладка не обновится.
- Объективно: `status` (focus, mins), rec2.

**T9. Долгая сессия (утечки, S8).**
- Действие: скриптом открыть и закрыть 300 окон TextEdit/Finder по одному (или 70 вкладок Ghostty и держать
  их открытыми).
- Ожидается: после ~256 разных wid — новые окна не тайлятся (`configure … ошибка -1`, `ax_tileable` = -1);
  после 64 живых слотов — команды движку теряются (`h.errors` растёт; читать из chan).
- Объективно: `h.errors`, число `used` слотов, строки «ошибка -1» в логе.

## 4. Шаги для основного агента (по убыванию отдачи), у каждого — проверка

1. **S1 вкладки**: в `sync` при переименовании листа вернуть α=1 новому окну и `OP_FORGET` старому.
   Проверка: T7 — в rec2 после Cmd+T содержимое новой вкладки видно в плитке ≤2 кадров; `cur_alpha` = 1.
2. **S2 минимумы**: учить минимум по `got > to + TOL` у стабильного окна независимо от `pre`; в tile.need —
   `max(learned, default)`. Проверка: T5 — после одного прохода `minsize_app.json` содержит ширину Telegram,
   строк «держу в плитке» для него больше нет, правый нижний угол скруглён.
3. **S3 configure**: одна очередь на окно, отмена устаревших целей, один поток на приложение.
   Проверка: T1/T2 — через 1 с после серии все `real` = цели (±TOL).
4. **S4 EV_MOVED** в движке + реакция демона. Проверка: вручную (AX из стороннего скрипта) сдвинуть окно в
   плитке → демон возвращает его за ≤100 мс, в логе событие.
5. **S8.1/S8.2 утечки**: `ax_forget` и `forget` на `EV_GONE`; вытеснение в AX-кэше; демон логирует рост
   `h.errors`. Проверка: T9.
6. **S6 holding**: держать только окна пачки с `needs`, альфу не держать. Проверка: T2 — нет плато у едущих окон.
7. **S7 hide** через отдельный Space (`SLSMoveWindowsToManagedSpace` 186fee37c), unhide — на текущий стол.
   Проверка: T4(в) — окно возвращается на текущий стол; Mission Control не показывает скрытое окно.
8. **S9**: решить «сразу конечный размер» vs «по EV_DONE» и привести код/комментарий/HANDOFF к одному.
   Проверка: T6(а) — полосы подложки при росте соседей в rec2 (ширина полосы × длительность).
9. **S10**: простой тик движка ≥16.7 мс; цвет подложек через движок/`SLSHWCaptureWindowList`.
   Проверка: `h.ticks` в простое ≤60/с; Activity Monitor WindowServer CPU в простое до/после.
